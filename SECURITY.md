# Security Policy

## Supported versions

Until the first stable release, security fixes are applied to the latest commit on `main`. After v1, this file will list supported release lines.

## Reporting a vulnerability

Use GitHub private vulnerability reporting from the repository's **Security** tab. Do not open a public issue for suspected vulnerabilities and do not include credentials, tokens, private keys, enterprise data, or personally identifiable information in a report.

Include the affected component, reproduction conditions, potential impact, and any suggested mitigation. Maintainers should acknowledge a complete report within five business days and coordinate disclosure after a fix is available.

## Scope priorities

Reports involving cross-scope authorization, GitHub App credentials, Microsoft Entra role bypass, forged workflow callbacks, duplicate or conflicting financial writes, signed report downloads, audit tampering, or exposure of user-level metrics receive priority review.
